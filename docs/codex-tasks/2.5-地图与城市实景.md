- 不要标题栏、刷新按钮、底部状态、"x 分钟前"之类文字。截图只在左下角用小号白字（带极淡的半透明深色胶囊底，保证可读）显示城市中文名。

## 2. 世界地图

### 2.1 地图数据（离线、内置）
- 使用 Natural Earth 1:110m Admin 0 Countries（公有领域）：`https://raw.githubusercontent.com/nvkelso/natural-earth-vector/master/geojson/ne_110m_admin_0_countries.geojson`（约 800 KB，此机器网络较慢，curl 请设 `--max-time 120`）。原始 geojson 不要提交进仓库。
- 新建 `Tools/build_world_map.py`（提交进仓库）：读取上述 geojson，输出 `Sources/WorldMapData.swift`。每个国家保留：`ISO_A3`（遇到 `-99` 改用 `ADM0_A3`）、英文名 `NAME_EN`（缺失用 `NAME`）、`CONTINENT`、`LABELRANK`、`LABEL_X`、`LABEL_Y`、多边形。多边形用 Douglas-Peucker 简化（容差约 0.25°），坐标量化为 0.1° 整数，用紧凑文本编码放进**一个**字符串字面量（不要写成巨大的 Swift 数组字面量，会拖慢编译），运行时用 `static let` 懒解析一次。目标文件 ≤ 400 KB。
- `Sources/WorldMap.swift`（App 与 Widget 两个 target 都编译）：解析数据、投影、标签选择、昼夜线、热点匹配等纯逻辑，便于测试。

### 2.2 绘制
- SwiftUI `Canvas`，等距圆柱投影（经度线性、纬度线性），全球视图纬度范围约 −58°…+82°（去掉南极）。
- 陆地填充 `Color.primary.opacity(0.10)`，国界 `Color.primary.opacity(0.18)` 0.5pt，海洋透明。整体克制、偏暗，参考用户提供的深色世界地图截图风格。
- **国家英文标签**：字号 8.5–10pt、半粗、`.secondary`。按"重要程度与大小"取舍：先按 `LABELRANK` 升序，再按多边形面积降序；贪心放置，与已放标签矩形相交就跳过、超出地图边界就跳过。标签数随可用面积自然变化（全球超大号约 20–30 个），结果要确定（同输入同输出）。
- **地图范围**（App 设置）：全球、亚洲、欧洲、北美洲、南美洲、非洲、大洋洲、中东。每个预设是一个经纬度包围盒，按组件宽高比扩展到不变形。默认「全球」。

### 2.3 图层（App 设置里可分别开关，默认全开）
1. **地震**：USGS 数据已在抓取（`parseFeed` 的 `usgs` 分支），解析时额外读 `geometry.coordinates`（`[经度, 纬度, 深度]`）。红色实心圆，半径随震级增大，M6.5 以上加一圈淡色光晕。
2. **灾害预警**：GDACS RSS 每个 item 有 `geo:Point` 下的 `geo:lat`、`geo:long`（请用真实数据确认字段名；`RSSReader` 现在只取 item 的一级子元素，需要支持取到这两个嵌套元素）。红色预警红色、橙色预警橙色。
3. **昼夜分界**：按当前条目时间计算太阳直射点，夜半球叠加 `Color.black.opacity(0.22)`；纯本地计算，不联网。
4. **新闻热点**：取最近 24 小时的新闻，标题里出现某国英文名（用地图数据里的英文名，外加 `United States`/`US`/`U.S.`、`UK`/`Britain` 等常见别称）或中文名（为约 60 个主要国家内置中文别名表，如 以色列、伊朗、乌克兰、俄罗斯、美国、日本、台湾、朝鲜……）即计数；`isNoteworthy` 为真的报道权重 ×2。在该国标签点画琥珀色半透明圆，半径随计数增大，最多显示 12 个。
   - 说明：曾考虑 GDELT GEO API，实测返回 404 已不可用，所以改用本地新闻标题匹配。界面与文档要写明「按新闻提及量估计，非核实的冲突数据」。

### 2.4 数据模型改动
- `WorldEvent` 增加可选 `latitude: Double?`、`longitude: Double?`（Codable 可选字段，旧缓存必须仍能解码——现有测试里有旧 JSON 兼容用例，保持通过）。
- 组件时间线条目当前会清空 `sourceFeeds` 里的事件以减小体积（`widgetTimeline`）。地图需要的点请在 provider 里预先算好（地震／灾害点、热点列表），放进新的条目类型里，不要把完整来源数据塞进 60 个条目。

## 3. 城市实景截图

### 3.1 城市
固定 10 个：北京、上海、香港、重庆、东京、台北、纽约、洛杉矶、巴黎、伦敦。App 设置中选 **4 个**并可调整顺序（组件按此顺序显示），默认 北京、东京、纽约、伦敦。存进 App Group 偏好（键名如 `cameraCities`）。

### 3.2 截图来源（每城配多个候选，按优先级尝试）
为每个城市定义候选列表，类型：
- `.youtubeSearch(query)`：请求 `https://www.youtube.com/results?search_query=<编码后的 query>&sp=EgJAAQ%253D%253D`（`sp` 参数是"仅直播"筛选），设置浏览器 User-Agent 和 `Accept-Language: en`，从 HTML 中按出现顺序提取去重的 `"videoId":"<11位>"`；取前几个，缩略图地址 `https://i.ytimg.com/vi/<id>/hqdefault_live.jpg`（失败再试 `hqdefault.jpg`）。YouTube 会每隔几分钟刷新直播缩略图，所以同一地址反复抓也会变化。解析出的 videoId 缓存 6 小时，避免频繁搜索。点击目标：`https://www.youtube.com/watch?v=<id>`。query 示例：`"tokyo shibuya live camera"`、`"new york times square live"`、`"hong kong victoria harbour live"`、`"taipei live camera"`、`"paris eiffel live cam"`、`"london live camera"`、`"los angeles live cam"`、`"beijing live"`、`"shanghai bund live"`、`"chongqing live"`。请逐个实测，给每城挑效果好的 1–2 条 query。
- `.bilibiliRoom(roomID)`：`https://api.live.bilibili.com/room/v1/Room/get_info?room_id=<id>`（实测可访问），JSON 里 `data.live_status == 1` 时使用 `data.keyframe`（B 站定时生成的真实直播截图；若为 `http://` 改成 `https://`）。点击目标 `https://live.bilibili.com/<id>`。B 站搜索接口返回 412（风控），**不要**用搜索接口；房间号请你人工找一些长期开播的城市实景／天气镜头直播间，实测可用后写死在候选里，主要用于北京、上海、重庆。
- `.jpeg(url, page)`：官方公开摄像头静态图。已实测可用：香港天文台 `https://www.hko.gov.hk/wxinfo/aws/hko_mica/hk2/latest_HK2.jpg`（同站还有其他镜头编号，可挑维港方向的）。可尝试（本机测试时超时，请自行复测，能用才加）：伦敦 TfL JamCam（`https://api.tfl.gov.uk/Place/Type/JamCam` 列表里的 `imageUrl`）、纽约 NYC DOT（`https://webcams.nyctmc.org/api/cameras`）、洛杉矶 Caltrans CCTV。
- **禁止**：抓取 SkylineWebcams（其服务条款禁止抓取转用）、使用 yt-dlp/ffmpeg 下载或截取视频流、需要用户注册的 API 密钥。

### 3.3 抓取与存储
- 新建 `Sources/CameraSnapshots.swift`（App 与 Widget 都编译）：城市与候选定义、解析函数（videoId 提取、B 站 JSON 解析）、存储读写、轮换索引计算。
- 每个城市每轮最多保留 **3 张**来自不同候选（不同 videoId／房间／镜头）的画面，用于冷却期间轮播。图片用 ImageIO 缩到最长边 640px、JPEG 质量约 0.7 后写入 App Group：`WorldWatch/Cameras/<cityID>/<n>.jpg`，另写 `manifest.json`（每张的来源类型、点击地址、抓取时间）。写入用临时文件 + 原子替换，读写失败不崩溃。
- 校验：HTTP 200、`Content-Type` 是图片、字节数 > 5 KB（排除灰色占位图）、能解码。某候选失败就试下一个；整个城市都失败时**保留上一轮的图片**。
- 抓取间隔：App 设置可选 5／10／15／30 分钟，默认 10 分钟，存 App Group 偏好（如 `cameraInterval`）。
- **App 运行时**：独立于新闻检查的循环（参考 `EventStore.start()` 的写法，用 `await Task { … }.value` 隔离，避免修改间隔时取消进行中的请求）；只抓已选中的 4 个城市；并发上限 4；每个请求超时约 15 秒；抓完后 reload 截图相关的组件。
- **App 未运行时**：组件 provider 在 `getTimeline` 里发现最新截图早于"2 × 间隔"时，自行抓一轮（总时长控制在约 20 秒内，每城只取 1 张），失败就用旧图。
- **轮换**：时间线条目 i 显示每个城市的第 `(i + 城市序号) % 该城张数` 张，让 4 格不同时切换；只有 1 张时保持不动。提供一个纯函数便于测试。
- 组件里加载图片：从文件读 `Data` → `NSImage` → `Image(nsImage:)`，`.resizable().scaledToFill()` 并裁切成圆角 8pt 的格子。没有图片时显示城市名 + 系统 `photo` 图标的占位。
