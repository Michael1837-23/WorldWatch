## 2. 来源池

### 2.1 数据模型
把候选从「每城一个固定列表」升级为「来源池」：

```swift
enum CameraPlatform: String, Codable { case youtube, bilibili, skyline, official }
struct CameraSource: Identifiable, Codable {   // 一个具体可抓图的镜头
    let id: String          // 稳定 ID，如 "youtube:dfVK7ld38Ys"、"bilibili:3291055"、"skyline:538"、"official:hko-hk2"
    let platform: CameraPlatform
    let title: String       // 平台上的标题，用于设置界面展示
    let imageURL: URL
    let page: URL           // 点击打开的观看页
}
```
- 每城的**固定候选**（人工实测后写死）与**搜索候选**（运行时发现）合并成该城的来源池；搜索发现的来源也进入池子并持久化（App Group 下 `WorldWatch/Cameras/sources.json`），下次直接复用，避免每轮都搜索。
- 每城目标：**至少 4 个已实测可用的固定候选，覆盖至少 2 个平台**（实在做不到的城市在汇报里说明）。

## 3. 真实画面识别（核心）

为每个来源维护健康记录（持久化到 App Group，例如 `WorldWatch/Cameras/health.json`）：

```swift
struct CameraHealth: Codable {
    var lastFetched: Date?
    var lastChanged: Date?        // 最近一次检测到画面有变化的时间
    var fingerprint: UInt64?      // 上一张图的感知哈希
    var sha256: String?           // 上一张图原始字节的哈希
    var unchangedCount: Int       // 连续未变化次数
    var failures: Int             // 连续失败次数
    var state: CameraSourceState  // .live / .unverified / .staticCover / .offline / .failing
    var cooldownUntil: Date?
}
```

判定规则（阈值写成常量，便于调整，测试覆盖）：
1. **请求失败**（非 200、非图片、解码失败、超时）：`failures += 1`；冷却时间按 10 分钟、30 分钟、2 小时、6 小时递增（指数退避）；状态 `.failing`。
2. **待机／离线图**：图片过小（最长边 < 200px 或字节数 < 5 KB）、几乎纯色（灰度标准差很低）、平台声明未开播（B 站 `live_status != 1`、YouTube 不再有 `LIVE_NOW`）、`Last-Modified` 超过 2 小时：状态 `.offline`，冷却 1 小时。
3. **静态封面检测**：每次成功取到图，计算 64 位差值哈希（dHash：缩到 9×8 灰度，相邻像素比较）和原始字节 SHA-256。与该来源上一次的结果比较：
   - 字节完全相同，或 dHash 汉明距离 ≤ 2，记为「未变化」，`unchangedCount += 1`；否则 `unchangedCount = 0`、`lastChanged = now`、状态 `.live`。
   - 两次比较的间隔至少 4 分钟，太近的比较不算数，避免平台缓存导致误判。
   - `unchangedCount >= 2`（即连续两轮以上没变化）判为 `.staticCover`，冷却 6 小时后重新验证。
   - 夜间画面变化可能很小：dHash 阈值偏保守，并用测试覆盖「轻微噪声算变化、完全相同算不变」。
4. **新来源**首次取到图，状态为 `.unverified`：可以显示，但排序低于 `.live`。

## 4. 选图与自动换源

- 每轮抓取时，每城按下面的优先级从来源池挑出**最多 3 个**用于轮播：先 `.live`（按 `lastChanged` 越近越靠前），再 `.unverified`；跳过处于冷却期的。平台尽量分散：同一平台的已 `.live` 来源超过 2 个时，优先取其他平台的。
- 被选中的来源抓图失败、或在这一轮被判为封面／离线时，**当轮**就从池子里顺延取下一个，直到凑满 3 张或池子用完；每城的时间预算沿用现有超时逻辑。
- 某城一张有效图都没有时，保留上一批图片（现有行为），设置里显示原因。
- 搜索类候选（YouTube / B 站）仍然缓存 6 小时；池子里 `.live` 来源少于 2 个时，允许提前重新搜索（最多每 30 分钟一次）。
- `manifest.json` 里每张图记录 `sourceID`、`platform`、`page`，点击小组件格子打开对应的观看页。
